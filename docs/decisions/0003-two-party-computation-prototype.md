# ADR-0003: 最初の暗号プロトタイプに2者間計算を使う

- 状態: 提案
- 日付: 2026-10-03

## 背景

[ADR-0002](0002-first-operation-mutual-match.md)では、2人が固定された選択肢から項目を秘密に選び、両者が選んだ共通項目だけを双方へ返すことにしました。次に、同じプライバシー要件で暗号方式、ライブラリ、実行構成、信頼の仮定を比較する必要があります。

選択肢を公開された順序のビット列で表すと、求める結果は2人の秘密ビット列の論理積です。最初のプロトタイプでは、この小さな計算を正しく表現できること、両者へ同じ結果を返せること、情報の流れを説明しやすいことを、巨大な集合に対する性能より優先します。

## 決定案

最初の暗号プロトタイプでは、ガーブルド回路によるsemi-honestな2者間計算を使います。実装候補は[EMP-sh2pc](https://github.com/emp-toolkit/emp-sh2pc)とし、まず安定版の0.3系を固定して小さな技術検証を行います。開発版はAPIが安定していないため、検証開始時に改めて採否を確認します。

各参加者は公開された選択肢と同じ長さの秘密ビット列を入力します。回路は位置ごとに論理積を計算し、その結果を両者へ公開します。共通しなかった項目と相手だけが選んだ項目は公開しません。

## 実行構成

- 2つのプロセスを、それぞれ参加者の代理として実行する
- 初期検証では同一端末上の別プロセスで動かし、各プロセスへ別々に入力する
- 次の段階で2台の端末間に広げる
- 中継サービスが必要な場合も、プロトコルメッセージの転送だけを担当させ、秘密入力と平文の結果を保存しない
- セッションごとに入力とプロトコル状態を破棄する

同一端末で動かす初期検証は暗号計算と出力を確かめるためのものであり、端末管理者から入力を隠せるという保証はしません。

## 信頼モデル

最初のプロトタイプでは、次を仮定します。

- 両参加者はsemi-honestであり、プロトコルには従うが、受信したメッセージから相手の入力を推測しようとする可能性がある
- 両参加者は、自分の入力と公開された共通項目から論理的に導ける情報を知る
- 通信の発生、相手、時刻、メッセージ量は隠さない
- 端末、OS、乱数生成器、採用ライブラリは侵害されていない
- 相手になりすます攻撃を防ぐ認証と、通信路を保護する仕組みは暗号計算とは別に必要である

次は保証しません。

- 不正な形式の入力、入力数の制限違反、プロトコルからの逸脱を行うmaliciousな参加者への耐性
- 同じ相手との反復実行や複数アカウントによる推測の防止
- 侵害された端末、画面の覗き見、結果受領後の共有への耐性
- 本番環境に必要な可用性、監査、依存関係の完全性

## 比較した選択肢

### 専用PSI

[VolePSI](https://github.com/ladnir/volepsi)などのPrivate Set Intersection実装は、集合の共通部分を効率よく求める用途に近く、将来選択肢が大規模になった場合の有力候補です。Circuit PSIでは結果を秘密分散したまま後続計算へ渡せます。一方、最初の小さな固定選択肢では導入する依存関係とプロトコルの複雑さが大きく、双方へ同じ平文結果を返す処理も別途設計する必要があります。

### 汎用MPCフレームワーク

[MP-SPDZ](https://github.com/data61/MP-SPDZ)は、semi-honestからmaliciousまで複数の方式を同じ計算で比較できます。後に信頼モデルを強くする検証には有用ですが、最初の2者・小規模な論理積だけを試すには構成要素が多いため、第二候補とします。

### OPRFを使った独自PSI

[RFC 9497](https://www.rfc-editor.org/rfc/rfc9497.html)のOPRFはPSIを構成する部品になり得ますが、OPRF単体はPSI全体の入力検証、集合比較、双方への出力を定義しません。独自にプロトコルを組み立てることは避けます。

### ゼロ知識証明またはFHE

ゼロ知識証明だけでは、2人の入力を互いに隠したまま共通項目を双方へ返す計算を直接構成できません。FHEでは復号鍵を誰が持つかという追加の信頼設計が必要です。どちらも将来の比較対象には残しますが、最初の実装には選びません。

## 技術検証の合格条件

- 2つのプロセスが異なる秘密ビット列を入力できる
- 両者が同じ共通項目だけを受け取る
- 共通しない項目がプロトコルの出力、通常ログ、エラーログへ現れない
- 入力なし、共通項目なし、複数の共通項目を含むテストが通る
- 同一の公開選択肢と入力上限を両者へ適用できる
- セッション終了後に入力と一時状態を永続保存しない
- 実行手順、採用バージョン、デモ用途に限る保証範囲を再現可能な形で文書化する

## 影響

- ADR-0002の操作を小さなブール回路として直接表現できる
- semi-honestという限定された保証から始めるため、malicious耐性を本番相当の保証として誤認させない表示が必要になる
- EMP-sh2pcとC++のビルド環境が必要になる
- 2台の端末やWeb UIへ広げる前に、認証、通信路保護、中継方法を別の決定として記録する必要がある
- 技術検証でビルド、出力制御、運用が難しい場合は、同じ回路をMP-SPDZで実装して比較する

## 採用条件

このADRは、次の点をレビューして合意した時点で採用します。

- 最初の保証をsemi-honestに限定してよいか
- 同一端末の2プロセスから検証を始めてよいか
- EMP-sh2pcを最初の実装候補としてよいか
- malicious耐性と反復照合対策を後続マイルストーンにしてよいか
