# ADR-0002: 最初の操作を1対1の相互一致判定にする

- 状態: 採用
- 日付: 2026-10-02

## 背景

ADR-0001では、暗号方式より先に具体的な操作とプライバシー上の約束を決めることにしました。最初のプロトタイプでは、暗号技術の違いではなく、秘密の入力から必要最小限の結果だけを得る体験を検証する必要があります。

## 決定

2人の参加者が、セッションごとに同じ固定された選択肢の集合から1つ以上を秘密に選びます。両者が選んだ共通項目を、それぞれの参加者へ返します。共通項目がない場合は、一致しなかったことを返します。

最初の操作では、次を返しません。

- 一致した項目数
- 相手が選んだ項目
- 相性スコア

ここで「相手が選んだ項目」とは、共通項目ではない相手だけの選択を指します。一致した項目数は共通項目から分かるため、独立した結果としては返しません。

両者は同じ結果を受け取ります。結果を片方だけに返す操作、自由入力、3人以上のグループ照合、継続的なプロフィール保存は対象外とします。

## プライバシー上の約束

### 入力

- 各参加者の秘密: そのセッションで選んだ項目
- 公開情報: 選択肢の集合、セッション参加者、判定規則

### 開示する情報

- 各参加者: 両者が選んだ共通項目。共通項目がない場合は、一致しなかったこと
- 運営者または計算サービス: プロトコル実行に不可欠と判断した情報だけ。具体的な範囲は暗号方式と実行構成を選ぶADRで定める
- 外部の観測者: 内容は開示しない。ただし、通信の発生や時刻などのメタデータを最初のプロトタイプでは完全には隠さない

### 保証しないこと

- 参加者は自分の入力と結果を組み合わせて、相手の入力について推測できる
- 選択肢の総数、各参加者が選べる数、同じ相手との反復回数の組み合わせによっては、共通しなかった相手の入力も推測しやすくなる
- 相手、運営者、計算サービスの共謀に対する保証は、実行構成を決めるまで主張しない
- 参加者端末の侵害、画面の覗き見、結果受領後の自発的な共有は防がない

## プロトタイプに必要な制約

- セッションごとに新しい入力を使い、初期版では入力を永続保存しない
- 同じ2人による反復照合に上限を設けられる設計にする
- 選択肢の具体的な内容と件数を決める際に、各項目のセンシティブさと、選択数・反復回数を組み合わせた推測可能性をレビューする
- ログへ秘密の入力や生の中間値を記録しない
- UIで「不一致は相手がどの項目も選ばなかったことを意味しない」と説明する

## 影響

- 共通項目を返すため、1ビットの一致結果より開示量は増えるが、結果を会話や次の行動へ直接つなげられる
- 1対1かつ固定選択肢に限定することで、複数の暗号方式を同じ要件で比較しやすい
- 共通しなかった相手だけの選択は開示しない
- 次のマイルストーンとして候補プロトコル、信頼モデル、反復照合への対策を比較する

## 採用時の確認事項

次の点をレビューし、この決定を採用しました。

- 1対1の操作が最初の作品として十分に意味を持つか
- 共通項目を双方へ開示してよいか
- 結果を両者へ同時に開示してよいか
- 固定選択肢の具体例に、不必要にセンシティブな内容が含まれないか
